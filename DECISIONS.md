# Engineering Decisions

This is the senior-level overhaul of the Kalshi trading bot, executed against
the published requirements. Decisions below are deliberate and documented so
future maintainers can challenge them with evidence.

## 1. Layered architecture, not a rewrite

The repo already has working pieces (web UI, NWS/ESPN integration, journal,
learner, paper bots). A full directory rewrite would break those without
adding edge. Instead the new disciplined pipeline lives in
`src/kalshibot/v2/` as a focused alpha stack with strict risk and execution
policy. The old code is preserved for the dashboard and educational
introspection — but `make paper` and `make run` invoke v2 only.

Modules under v2: `data/`, `signals/`, `strategy/`, `risk/`, `execution/`,
`backtest/`, `monitoring/`, `config/`. Each is self-contained.

## 2. We trust signals, not strategies

The previous "151 strategies via ensemble" approach is academic on event
markets. There is no real edge in EMA crossovers on a binary that resolves
in 4 days. We **drop those weights to zero in v2** and use exactly three
signal families, all backed by published research:

* **Mispricing vs base rate** (Wolfers-Zitzewitz; favorite-longshot bias)
* **Order-book imbalance + 5-min momentum** (Lehalle, Cont)
* **External anchors** (NWS for weather, ESPN for sports, FRED for econ)

Combined via **logistic stacking** trained on settled trades. We trade only
when `|fair_value - mid| >= 3¢` AND combined confidence `>= τ` (default 0.55).

## 3. Risk is non-negotiable

* Fractional Kelly capped at **0.25×** (not full, not half — quarter).
* Hard cap **$25 per contract** for the first 2 weeks of live trading.
* **Daily realized loss > 3% of bankroll → flatten all + halt for the day.**
* Per-genre and per-series correlation caps.
* `data/HALT` file checked **every loop iteration**; if present, all new
  orders refused. (Used by ops to remote-kill the bot.)

## 4. Execution is queue-aware

Passive limit `1¢` inside the prevailing spread. After 30s without fill,
escalate to mid. If edge has grown past `5¢`, **take immediately** (cross
the spread). Cancel-on-disconnect via Kalshi heartbeat + a 60s watchdog
that flattens if our process can't reach the API.

## 5. Backtest with realism

Event-driven backtester with **fees** (Kalshi 7¢ flat per trade for now —
see code for live override), **slippage** modeled as half-spread + queue
position, and **queue dynamics** (we never get filled at top-of-book unless
we cross). Report tracks Sharpe, hit rate, avg edge captured, max DD, P&L
by strategy → `BACKTEST_REPORT.md` regenerated by `make backtest`.

## 6. Paper mirrors live exactly

`make paper` runs the live polling + signal stack + risk gates exactly as
`make run` does, but the `LiveExecutor.send()` path is replaced by a
`ShadowExecutor` that writes to `data/paper_ledger.jsonl`. Same fees, same
slippage. The dashboard reads from the journal whether real or shadow.

## 7. Universe filter

Only trade markets where:
* Spread `≤ 4¢`
* 24-hour volume `≥ $500`
* Time-to-resolution between 1 hour and 14 days
* Open interest is meaningful (`> 100` contracts)

This kills 95% of the auto-generated baskets on Kalshi without us ever
guessing which series are popular.

## 8. SQLite snapshot cache

`data/markets.db` written every 30s during trading hours so we have a real
historical sample to backtest on without smashing the Kalshi API. Schema:
one row per (ticker, ts) with bid/ask/last/volume/OI.

## 9. Calibration before sizing

Raw model probability is passed through isotonic regression (already in
`calibration.py`) before Kelly sizing. Otherwise a 70%-confident YES at 50¢
is sized as 70% — but the model has historically been overconfident; the
calibrated number might be 60%, which is the right input to Kelly.

## 10. Operational: always have a kill-switch

* `data/HALT` flag file (touch it = stop trading, delete = resume).
* The same kill switch shows in the web UI Risk bar.
* `make halt` and `make resume` provided in Makefile.

## What I removed / cut down

* The 151-strategy ensemble is no longer the source of truth. The legacy
  `combiner.best_combination()` still runs for the dashboard's
  educational `Brain` view, but the live executor uses `v2.strategy.combine`.
* No more credential prompts in templates. Everything is `.env`-driven.
* No more "auto-start everything" in `setup-live`. Live trading must be
  explicitly invoked with `make run`. Paper is `make paper`.

## How to challenge these decisions

If you can show with a Sharpe-positive walk-forward result over 4 weeks of
real Kalshi data that, e.g., the EMA-crossover strategy adds positive OOS
expected value, **we will reinstate it** by adding it as a fourth signal
in the stacker. The architecture allows it. The default does not.
